# Building BYlink natively on Windows with MinGW

The Windows Makefile path does **not** require CMake, WSL, MSYS shell commands or GLFW. It builds `bylc.exe` directly with MinGW-w64 `g++`. BYGL programs use native Win32 + WGL and link only the Windows system libraries `opengl32`, `gdi32` and `user32`.

## Requirements

- MinGW-w64 with a C++20-capable `g++.exe`.
- GNU Make (`mingw32-make.exe` is fine).
- PowerShell (included with Windows).

Make sure `g++.exe` and `mingw32-make.exe` are on `PATH`.

## Build

Open PowerShell **in the extracted BYlink project folder** (the folder containing `Makefile`) and run:

```powershell
mingw32-make
```

This creates both `build\bylc.exe` and a fresh copy `bylc.exe` in the project root. Use the root copy in the following commands. Do not run an older `bylc.exe` from your Downloads folder.

## Unit tests

```powershell
mingw32-make test
```

This compiles and runs the platform-independent compiler, parser, BYAI, IR and BYGL tests.

## Compile your own BYGL program

Put `pong.bygl` in the project folder, or use a path to your file:

```powershell
.\bylc.exe .\pong.bygl -o .\pong.exe
```

Or compile the bundled Pong example:

```powershell
.\bylc.exe .\examples\pong_static.bygl -o .\build\pong.exe
```

Run it:

```powershell
.\pong.exe
```

Press Escape or close the window to exit.

## Compile the bundled OpenGL demo using Make

```powershell
mingw32-make opengl-demo
```

## Choose another C++ compiler

```powershell
mingw32-make CXX=clang++
```

## Troubleshooting

- `g++ was not found`: add the MinGW-w64 `bin` directory to Windows `PATH`.
- `make` was not found: run `mingw32-make`.
- `cmake` is not required by the Windows Makefile target.
- The generated BYGL executable does not need a separate GLFW installation on Windows. The backend uses Win32 window creation and WGL directly.
- BYGL uses legacy desktop OpenGL 2.1 fixed-function rendering. It is actual OpenGL, not a software drawing mockup.
- If you see `window expects 3 argument(s), got 4`, rebuild from this project folder with `mingw32-make`, then run ` .\bylc.exe ...` from the same folder. That message usually means an older compiler executable is being used.

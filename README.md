# BYlink

### More executable functionality. Less generated code.

**BYlink is an AI-oriented programming language and native compiler designed to transform compact LLM-generated programs into native executables.**

What if an AI model could generate a playable game or a 3D application without producing hundreds of lines of conventional C++?

BYlink explores a different approach: compact programming representations that allow AI models to describe functionality while the compiler handles implementation, rendering infrastructure and native code generation.

**Describe it. Generate it. Compile it. Run it.**

---

## Why BYlink?

Traditional AI-assisted programming often generates extensive source code, repetitive declarations, framework boilerplate and implementation details.

BYlink takes a different approach.

Instead of generating all the underlying implementation, an LLM describes the requested program using compact instructions. BYlink handles parsing, validation, code generation and native compilation.

The objectives are:

- Reduce the amount of code generated by LLMs.
- Reduce the context and output required to produce executable software.
- Avoid repetitive framework and rendering boilerplate.
- Generate native executables.
- Provide a consistent programming interface for different AI models.

**More functionality per generated instruction.**

## Token efficiency: preliminary Pong benchmark

Token efficiency is one of the main motivations behind BYlink.

An initial experiment compared two implementations of the same requested application:

- BYGL 2: compact graphics-oriented instructions.
- C++17: GLFW3 and OpenGL 2.1 compatibility mode.

The experiment also highlights an important distinction: the cost of generating a program includes not only the generated code, but also the instructions required to teach the model the target language.

### Why does BYGL require less generated code?

Conventional C++ explicitly implements infrastructure that BYGL provides through its compiler and runtime.

| Implementation detail | BYGL | C++ |
|---|---|---|
| Window creation | Built-in instruction | GLFW calls |
| Graphics context | Runtime-managed | Explicit setup |
| Frame loop | Runtime-managed | Explicit loop |
| Keyboard input | Compact key expressions | GLFW input calls |
| Rectangles and circles | Native instructions | OpenGL drawing code |
| Dynamic text | Built-in instructions | Custom rendering |
| Frame timing | Built-in `dt` | Clock and delta-time handling |
| Game logic | Compact expressions | Explicit C++ statements |

BYGL moves recurring implementation complexity into the compiler and runtime.

### Important: total token consumption is still under investigation

The figures above are preliminary estimates, not measured token usage.

A complete comparison must account for:

- Language specification tokens.
- Generation prompt tokens.
- Task description tokens.
- Generated source tokens.
- Additional context and conversation overhead.
- Model-specific tokenization.

The same tokenizer must be used for both implementations when measuring actual consumption.

The total calculation remains open because exact tokenizer identities and generation metadata are not available for the current experiment.

**BYlink's objective is to reduce the total cost of producing verified executable software, not merely to shorten source files.**

## Two programming paths

BYlink currently provides two complementary languages.

### BYAI — Computational programs

BYAI v1 is a compact intermediate representation for scalar computations and programs.

Features:
- Arithmetic and scalar operations.
- Typed program representations.
- Compact instructions.
- Native compilation through LLVM.

### BYGL — Graphics and interactive applications

BYGL is an LLM-oriented graphics language targeting native OpenGL applications.

**BYGL v1 — Static graphics**

- 2D and 3D scenes.
- Windows and backgrounds.
- Cameras and grids.
- Cubes, spheres and geometric primitives.
- Lines and text.

**BYGL v2 — Interactive applications**

- Persistent program state.
- Per-frame updates.
- Keyboard input.
- Conditional execution.
- Dynamic object positioning.
- Game logic and collision handling through program expressions.

BYGL v2 supports both static scenes and interactive applications.

Examples include animated 3D scenes and a two-player Pong game with keyboard controls, ball movement, collisions and scoring.

## From natural language to native executable

```text
Human Request
      |
      v
     LLM
      |
      v
 Compact BYAI / BYGL
      |
      v
  BYlink Compiler
      |
      v
 Native Code Generation
      |
      v
 Native Executable
```

The LLM does not need to generate the complete rendering infrastructure or application boilerplate.

It generates the compact program. BYlink handles the implementation.

## Build BYlink

### Linux / macOS

Requirements:
- C++20 compiler.
- CMake 3.20+.
- GNU Make.
- Clang for the native scalar BYAI backend.
- GLFW 3 and OpenGL development libraries for graphics applications.

Debian / Ubuntu:

```bash
sudo apt update
sudo apt install -y build-essential cmake make clang pkg-config libglfw3-dev libgl1-mesa-dev
```

Build and test:

```bash
make
make test
```

### Windows

Requirements:
- MinGW-w64.
- GCC / G++ with C++20 support.
- GNU Make.

Windows uses native Win32/WGL and does not require CMake or GLFW.

```powershell
mingw32-make
mingw32-make test
```

See `docs/BUILDING_WINDOWS.md`.

## Generate an OpenGL application with an LLM

Use the unified BYGL prompt:

`docs/LLM_BYGL_PROMPT.txt`

Replace `{{REQUEST}}` with your desired application.

Example:

> Create a 3D Pong game with two-player keyboard controls, ball physics, wall and paddle collisions, scoring and restart.

Save the generated response as `game.bygl`.

Linux:

```bash
./build/bylc game.bygl -o build/game
./build/game
```

Windows:

```powershell
.\build\bylc.exe game.bygl -o build\game.exe
.\build\game.exe
```

No manually generated C++ rendering boilerplate is required.

### Included examples

Static 3D scene:

```bash
./build/bylc examples/rotating_scene.bygl -o build/scene
./build/scene
```

Interactive Pong:

```bash
make pong-demo
```

Documentation:
- `docs/BYGL2.md`
- `docs/OPENGL.md`
- `docs/LLM_BYGL_PROMPT.txt`
- `examples/pong.bygl`

## Generate computational programs

Use `docs/LLM_PROMPT_TEMPLATE.txt` for BYAI v1.

Example:

```bash
./build/bylc examples/add.byai -o build/add
./build/add
printf 'exit code: %s\n' "$?"
```

The included example calculates `1 + 1` and returns `2` as its process exit code.

## Research: Beyond textual code generation

BYlink is also an experimental foundation for investigating more efficient communication between AI models and native compilers.

Research areas include:

- Compact intermediate representations.
- Cross-model compatibility.
- Neural representation alignment.
- Information compression.
- Token-efficiency benchmarking.
- Latent-space communication.
- Native executable generation from learned representations.

The long-term objective is to investigate whether different LLM families can transfer computational intent through compact representations rather than repeatedly translating entire programs into verbose conventional source code.

A trained universal neural encoder/decoder and teacher-free latent communication have not yet been demonstrated. These remain active research objectives.

## Benchmarking and reproducibility

BYlink aims to measure actual generation efficiency rather than rely on assumptions.

Future comparisons should use:
- The same LLM.
- The same tokenizer.
- Equivalent functional requirements.
- Prompt and output tokens measured separately.
- Compilation and execution validation.
- Multiple independent tasks.

A shorter program that does not work is not an optimization.

The meaningful metric is:

**Verified executable functionality per total generation token.**
